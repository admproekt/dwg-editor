# Работа в проекте

Проект — папка-репозиторий с файлом `project.json`. В ней исходники, модели, виды, журнал. Подробности о папках и правилах лежат в `CLAUDE.md` проекта, прочитайте его.

## Порядок

1. Начало сессии в проекте: `project_status`. Скажите инженеру стадию и что не закоммичено.
2. Новый исходник: `source_add` (копия в `sources/` с хэшем). Не копируйте файлы в `sources/` вручную. После правок «в обход» проверьте `sources_verify`.
3. Пути давайте относительно корня проекта. Писать можно только внутри проекта и не в `sources/`. Результаты: скрипты и промежуточное в `work/`, модели в `models/`, виды в `views/`, кадры и видео в `renders/` (не в git).
4. Журнал пишите сразу, когда принято решение, найдена ошибка или получен урок: `journal_add` с видом `решение`, `ошибка`, `урок`, `проверка`. Одна запись — один вывод, с причиной и ссылкой на файл. Журнал нужен, чтобы из него потом собирать навыки, пишите так, чтобы поняли без вас.
5. Конец стадии: `project_stage`, затем `project_commit` с сообщением, что сделано. Версию модели отмечайте `project_tag`. Ничего не отправляйте на сервер, пока инженер не попросил: тогда `project_publish`. Чужой проект с сервера берёт `project_clone` (адрес и папку спросите). Обмен после первой отправки идёт командами git (`git pull --rebase`, `git push`), инструкция в `docs/git-server.md`.

## Чего не делать

- Не создавайте проект внутри другого git-репозитория, в том числе внутри репозитория плагина.
- Не правьте исходники. Нужна правка — сохраните копию в `work/` или `models/`.
- Не коммитьте `renders/`: кадры и видео воспроизводимы из рецептов.
- Вывод, сделанный по одному образцу, помечайте как предположение и проверяйте на следующем чертеже.
