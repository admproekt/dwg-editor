# cad-project — проекты инженера как git-репозитории

Проект — обычная папка с файлом `project.json`, внутри которой git-репозиторий (пока без `origin`). В ней лежат исходные чертежи, модели, виды, журнал решений. Плагины `dwg-editor` и `3d-editor` работают относительно этой папки, так что проект можно перенести, открыть на другом компьютере и в будущем отдавать коллегам через сервер git.

## Установка

```bash
claude plugin marketplace add admproekt/dwg-editor
claude plugin install cad-project@dwg-tools
```

Нужны Python 3.10+ и git. `git-lfs` желателен: тогда большие файлы (чертежи, IFC, видео) хранятся через LFS и репозиторий не раздувается.

## Начало работы

1. `/project-new C:\Projects\Сириус`: создаётся каркас, `git init`, первый коммит. Папка должна быть вне других репозиториев.
2. Откройте приложение в папке проекта: тогда агент сам прочтёт `CLAUDE.md` проекта.
3. Исходные файлы вносите инструментом `source_add` (копия в `sources/` и хэш). Результаты кладите в `work/`, `models/`, `views/`.
4. Решения и уроки записывайте в журнал (`journal_add`), в конце стадии `project_stage` и `project_commit`.
5. В другой день: `/project-open <папка>` или просто откройте приложение в папке проекта.

## Что в папке проекта

```
CLAUDE.md          инструкции агенту (блок между маркерами обновляется, ваш текст остаётся)
project.json       название, вид, СК, единицы, стадии
sources/           исходные данные, только чтение, sources.json с хэшами
work/              скрипты и промежуточные данные
models/            IFC, OBJ, GLB
views/             сохранённые виды и пути камеры
recipes/           рецепты рендера и видео
renders/           кадры и видео, не в git
journal/           журнал по датам
skills-draft/      черновики навыков из этой работы
.claude/skills/    навыки, выбранные для проекта
```

## Как это влияет на другие плагины

Пока открыт проект, `dwg-editor` и `3d-editor` считают относительные пути от его корня, пишут только внутри проекта и не пишут в `sources/`. Чтобы сохранить правку исходного чертежа, сохраните копию в `work/` или `models/`. Без проекта всё работает как раньше. Проект находится так: переменная `CAD_PROJECT_ROOT`, затем папка запуска и её родители, затем последний `project_open`. Снять проект: `project_close`.

## Инструменты

| Инструмент | Что делает |
| --- | --- |
| `project_init`, `project_open`, `project_close` | Создать, открыть, снять проект |
| `project_status`, `project_set`, `project_stage` | Статус, имя, вид, СК и единицы, стадии |
| `source_add`, `sources_verify` | Внести исходник, проверить хэши |
| `journal_add` | Запись в журнал: решение, ошибка, урок, проверка, заметка |
| `project_commit`, `project_tag`, `project_log` | Коммит, версия тегом, история |
| `project_publish` | Подключить сервер git и отправить ветку, теги, файлы LFS (по просьбе инженера) |
| `project_clone` | Скопировать проект с сервера в новую папку, скачать LFS, проверить исходники |

## Сервер и совместная работа

Свой git-сервер в локальной сети (Gitea, LFS, пользователи, резервные копии): [docs/git-server.md](docs/git-server.md). Команды `/project-publish <адрес>` и `/project-clone <адрес> <папка>`. Дальнейший обмен между инженерами пока командами git (`git pull --rebase`, `git push`), см. раздел 6 инструкции.
