# Свой git-сервер в локальной сети (Gitea)

Инструкция для небольшой команды инженеров в одной сети. Сервер хранит проекты как git-репозитории вместе с большими файлами (чертежи, тома, IFC, OBJ, видео) через Git LFS. Выбрана **Gitea**: один исполняемый файл, база SQLite, веб-интерфейс, пользователи и права, LFS из коробки. Подходит и Forgejo (форк Gitea), шаги те же.

Почему не «просто git по SSH» и не общая сетевая папка: чистый git по SSH не обслуживает LFS, а общая папка не рассчитана на запись нескольких человек в один репозиторий и может его повредить.

Что нужно:
- компьютер или виртуальная машина, которые включены всегда (мини-ПК, NAS, сервер); Windows или Linux;
- на нём установлен git (Gitea вызывает его сама);
- место на диске: размер всех проектов с запасом ×3 на историю версий;
- фиксированный адрес в сети: резерв в роутере (DHCP reservation) или имя компьютера.

Ниже `СЕРВЕР` — имя или IP этого компьютера (например `192.168.89.10`).

## 1. Установка на Windows

1. Установите git на сервере: `winget install Git.Git`.
2. Скачайте Gitea: на сайте gitea.com в разделе загрузок выберите сборку для Windows amd64. Положите `gitea.exe` в `C:\gitea`.
3. Запустите один раз для настройки: в PowerShell `cd C:\gitea; .\gitea.exe web`. Откройте в браузере `http://СЕРВЕР:3000`.
4. На странице первоначальной настройки:
   - База: **SQLite3**.
   - Домен сервера: `СЕРВЕР`. URL приложения: `http://СЕРВЕР:3000/`. Именно по этому адресу git и LFS будут ходить, поэтому не оставляйте `localhost`.
   - Корень репозиториев и путь LFS оставьте внутри `C:\gitea\data`.
   - «Отключить самостоятельную регистрацию» отметьте: пользователей заводит администратор.
   - Задайте учётную запись администратора и нажмите «Установить».
5. Остановите (Ctrl+C) и откройте `C:\gitea\custom\conf\app.ini`. В разделе `[server]` должно быть:

   ```ini
   LFS_START_SERVER = true
   ```

   Если строки нет, добавьте. Без неё большие файлы отправить не получится. В новых версиях ключ создаётся мастером, но проверьте.
6. Запустите как службу, чтобы сервер жил после перезагрузки. В PowerShell от администратора:

   ```powershell
   sc.exe create gitea start= auto binPath= "\"C:\gitea\gitea.exe\" web --config \"C:\gitea\custom\conf\app.ini\""
   Start-Service gitea
   ```

7. Откройте порт для локальной сети (только частный профиль):

   ```powershell
   New-NetFirewallRule -DisplayName "Gitea" -Direction Inbound -Protocol TCP -LocalPort 3000 -Profile Private -Action Allow
   ```

Linux: скачайте бинарник, создайте пользователя `git`, запустите через systemd (`gitea web`), шаги 4–5 те же. Подробности в документации Gitea, раздел установки из бинарного файла.

## 2. Пользователи и права

1. Войдите администратором. «Администрирование сайта» → «Учётные записи» → создайте инженеров (логин, почта, временный пароль; просите сменить).
2. Создайте организацию (например «Проекты») и команду «Инженеры» с правом записи. Добавьте в неё людей. Репозитории проектов создавайте внутри организации: права выдаются командой, а не на каждого отдельно.
3. Каждому инженеру: «Настройки» → «Приложения» → создать **токен доступа** с правом на репозитории (чтение и запись). Токен вводится вместо пароля при работе с git и запоминается менеджером учётных данных Windows (он идёт вместе с Git for Windows).

## 3. Создание репозитория проекта

В организации: «Новый репозиторий», имя латиницей (`sirius`), **приватный**, **без README, .gitignore и лицензии**: репозиторий должен быть пустым, иначе история расходится и отправка отклонится.

Адрес будет вида `http://СЕРВЕР:3000/Проекты/sirius.git`.

## 4. Отправить проект на сервер

В Claude Code с плагином `cad-project` и открытым проектом:

```
/project-publish http://СЕРВЕР:3000/Проекты/sirius.git
```

Команда проверит доступ, добавит `origin`, отправит ветку `main`, теги и файлы LFS. Если запросит вход, в терминале один раз выполните `git ls-remote http://СЕРВЕР:3000/Проекты/sirius.git`, введите логин и токен вместо пароля, затем повторите.

Первая отправка больших проектов (гигабайты) идёт долго. Тогда надёжнее терминал, из папки проекта:

```bash
git remote add origin http://СЕРВЕР:3000/Проекты/sirius.git
git push -u origin main
```

Проверка: в веб-интерфейсе откройте `sources/` в репозитории, у `.dwg` и `.pdf` должна стоять пометка «Хранится в Git LFS».

## 5. Коллегам: получить проект

```
/project-clone http://СЕРВЕР:3000/Проекты/sirius.git C:\Projects\Сириус
```

Плагин скопирует репозиторий, скачает файлы LFS, сверит хэши исходников и сделает проект активным. Нужны git и git-lfs (`winget install Git.Git GitHub.GitLFS`). В терминале то же самое: `git clone <адрес> C:\Projects\Сириус`, затем `git lfs pull`.

## 6. Ежедневная работа вдвоём и больше

Плагин пока отправляет проект один раз и копирует его; дальнейший обмен делается командами git в папке проекта:

```bash
git pull --rebase     # забрать чужие изменения перед работой
git push              # отправить свои коммиты
```

Правила, чтобы не ссориться с бинарными файлами (DWG, IFC не сливаются автоматически):
- один файл правит один человек за раз; кто правит, договаривайтесь в чате или используйте блокировки LFS: `git lfs lock models/Общий.ifc`, после коммита `git lfs unlock`;
- у каждого свои скрипты и модели в разных именах (`work/<инженер>/...`) или в своей ветке (`git switch -c ivanov/profile`), слияние в `main` после проверки;
- журнал `journal/` ведётся по датам, файлы разные, конфликтов обычно нет;
- `renders/` в git не попадает: кадры и видео воспроизводятся из рецептов.

## 7. Резервные копии

Сервер не должен быть единственным местом хранения. Раз в сутки, по расписанию:

```powershell
Stop-Service gitea
C:\gitea\gitea.exe dump -c C:\gitea\custom\conf\app.ini -f D:\backup\gitea-$(Get-Date -Format yyyyMMdd).zip
Start-Service gitea
```

Копию уносите на другой диск или компьютер. Дополнительно: у каждого инженера на компьютере полный клон. Раз в месяц проверьте, что архив разворачивается.

## 8. Обновление

Сделайте резервную копию, остановите службу, замените `gitea.exe` новой версией, запустите службу. Читайте заметки о версии, прежде чем менять мажорную версию.

## 9. Безопасность

- Сервер в локальной сети по обычному http: пароли и токены идут открыто. Не открывайте порт наружу (роутер, проброс портов). Для доступа вне офиса нужен HTTPS (Caddy или nginx перед Gitea с сертификатом) или VPN.
- Репозитории приватные, регистрация выключена, токены выдавайте с минимальными правами и отзывайте у ушедших.
- В `sources/` лежат данные заказчика: давайте доступ только участникам проекта.

## 10. Если что-то не работает

| Симптом | Причина и что делать |
| --- | --- |
| Адрес не открывается с другого компьютера | Брандмауэр сервера: правило из шага 1.7; проверьте `Test-NetConnection СЕРВЕР -Port 3000` |
| `Authentication failed` | Вводили пароль вместо токена или токен без прав на репозитории; очистите запись в «Диспетчере учётных данных» Windows и войдите заново |
| Ошибка LFS при отправке, 404 или 501 | `LFS_START_SERVER = true` не включён в `app.ini` или службу не перезапустили |
| Отправка отклонена (`rejected`, `fetch first`) | На сервере уже есть коммиты (создан README): создайте пустой репозиторий заново или сделайте `git pull --rebase` |
| Файлы после клона текстовые, по сто байт | Не установлен git-lfs: поставьте и выполните `git lfs install; git lfs pull` |
| Отправка гигабайтов обрывается по времени | Выполняйте в терминале, повторите `git push`: LFS докачивает недостающее |
