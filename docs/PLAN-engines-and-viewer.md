# План: движки правки DWG и web-просмотрщик

Статус: черновик плана. Цены, лимиты и возможности внешних продуктов ниже даны по общим знаниям и не проверялись, их нужно сверить на этапе прототипа.

## 1. Цели

1. Сохранить `ezdxf` для простых задач: он бесплатный, быстрый и не требует AutoCAD.
2. Добавить движки на базе AutoCAD для того, с чем `ezdxf` не справляется: динамические блоки, прокси-объекты, сложные внешние ссылки и другие объекты, которые знает только AutoCAD.
3. Сделать выбор движка пошаговым и предсказуемым: одни и те же инструменты MCP, разные движки под ними.
4. Сделать web-просмотрщик во встроенном браузере Claude Desktop: смотреть чертёж, выделять участки и объекты, писать агенту, что в них изменить, и видеть результат.

## Принятые решения

- Версия AutoCAD: 2026, лицензия сетевая коммерческая.
- Коннектор AUTOM8LABS: только Free и только если понадобится для чтения. Pro не покупаем, запись в живой AutoCAD делаем собственным мостом (сначала COM).
- Примеров чертежей с динамическими блоками и прокси-объектами пока нет, поэтому тесты начинаются на синтетических чертежах, реальные добавим, когда появятся.
- Порядок работ: этапы 0 и 1 (основа и слой `ezdxf`), затем просмотрщик, затем движки на базе AutoCAD.

## 3. Порядок выбора движка

Движки перебираются сверху вниз, берётся первый подходящий.

| Шаг | Условие | Движок |
| --- | --- | --- |
| 1 | Простая задача, объекты не требуют AutoCAD | `ezdxf` |
| 2 | Нужна совместная работа: чертёж открыт у пользователя, агент правит его там же | Живой AutoCAD |
| 3 | Сложный объект, но живой сеанс не нужен: пакетная или фоновая правка файла | AutoCAD Core Console |
| 4 | AutoCAD не установлен, а сложный объект править надо | Autodesk Platform Services |

Что считать «сложным объектом» (требует AutoCAD): правка параметров динамических блоков, прокси-объекты других приложений, аннотативные масштабы, таблицы `ACAD_TABLE`, наборы листов, печать. Список уточняется по результатам тестов (раздел 7).

Как это реализуется:
- Инструмент `engine_status` сообщает, какие движки доступны: `ezdxf` всегда, живой AutoCAD (найден ли запущенный экземпляр), Core Console (найден ли `accoreconsole.exe`), APS (заданы ли учётные данные).
- Новый навык `engine-selection` описывает таблицу выше для агента. Проверки есть и в коде сервера: если объект требует AutoCAD, а доступен только `ezdxf`, инструмент возвращает понятную ошибку с предложением.
- Инструменты остаются теми же (`open_drawing`, `list_entities`, `modify_entity` и так далее) с необязательным параметром `engine`. Навыки по типам чертежей от движка не зависят.
- Правка через APS всегда требует явного подтверждения пользователя: файл покидает компьютер.

### 4.1 Живой AutoCAD

1. **Коннектор AUTOM8LABS: решено.** Pro не покупаем. На Free он доступен для чтения (в том числе `get_dynamic_block_properties`) и используется только при необходимости. Запись строим своим мостом.
2. **Прототип на COM** (Python, `pywin32` или `comtypes`): подключиться к запущенному AutoCAD, прочитать и изменить свойство динамического блока, сохранить. Проверить на AutoCAD 2026.
3. **Решение о .NET.** Если нужны события (чертёж изменился) и скорость, написать плагин на .NET (управляемый API AutoCAD), загружаемый в AutoCAD, с каналом связи с MCP-сервером. Иначе остаться на COM.
4. **LISP** оставить как запасной способ для коротких макросов.
5. **Правила совместной работы.** Агент правит через очередь команд, каждая правка в отдельной группе отмены, при занятом AutoCAD (команда выполняется, открыт диалог) ждёт. Режим «только чтение» включается по умолчанию. Перед массовой правкой создаётся контрольная точка.
6. **Что важно учесть в мосте по справке Autodesk** (источники в разделе «Источники»):
   - Подключаться через `AutoCAD.Application` (последняя установленная библиотека) или явно через `AutoCAD.Application.25.1`: по таблице справки это AutoCAD 2026, библиотека типов `acax25.tlb`.
   - `SendCommand` с AutoCAD 2015 выполняется асинхронно: вызывающий код ждёт, пока последняя команда из строки не завершится или не будет прервана. Поэтому команду с аргументами нужно отправлять одной строкой целиком, например `._LINE 0,0 5,5 `. Вторая часть, отправленная отдельным вызовом, уйдёт уже после завершения команды.
   - `PostCommand` ставит строку команды в очередь, и она выполняется, когда документ простаивает. Подходит, если длинную команду нужно разбить на несколько строк. Это единственный случай, где он нужен.
   - Когда есть объектная модель (свойства объектов, динамические свойства блоков), использовать её, а не команды. Команды только там, где API нет.
   - Объекты в справке адресуются по `Handle` и `HandleToObject(handle)`. Наши инструменты тоже работают с `handle`. Совпадают ли `handle` у объектов после преобразования через ODA, нужно проверить на прототипе.
   - `SaveAs` больше не умеет ставить пароль на чертёж: защищённые паролем файлы таким путём не сохранить.
   - ActiveX в AutoCAD LT ограничен, а на Mac и в Web не поддерживается. У пользователя полный AutoCAD для Windows, поэтому это не мешает.

| API | Плюсы | Минусы | Роль |
| --- | --- | --- | --- |
| COM | Просто писать на Python, быстро получить прототип | Медленнее .NET, нет событий в том виде, в каком они нужны | Прототип, первая версия |
| .NET | Полный доступ, скорость, события, транзакции | Нужна сборка плагина на C#, версия под версию AutoCAD | Основной вариант, если COM не хватит |
| LISP | Быстро для коротких задач | Слабая структура, сложно сопровождать | Запасной вариант |

### 4.2 AutoCAD Core Console

1. Найти `accoreconsole.exe` (папка установки AutoCAD) и проверить, что запуск проходит с имеющейся лицензией.
2. Обёртка: копия чертежа во временную папку, генерация скрипта (`.scr` или вызов LISP и .NET), запуск с таймаутом, сбор журнала, возврат результата в новый файл.
3. Проверить ограничения: какие команды и объекты не работают без графики.
4. Те же операции, что в живом AutoCAD, за теми же инструментами MCP.
5. Справка Autodesk по Core Console в найденных материалах дана только ссылками (статья поддержки отсылает к разделу справки разработчика и докладу Autodesk University). Ключи командной строки `accoreconsole.exe` в найденном тексте не приведены, их нужно взять из справки разработчика или проверить запуском. Для обычного AutoCAD найден запуск скрипта при старте: `acad имя_чертежа /b имя_скрипта`, имя скрипта последним параметром.

### 4.3 Autodesk Platform Services

1. Завести учётную запись и приложение APS, хранить ключи в безопасном месте (не в репозитории).
2. Настроить Design Automation: пакет приложения (скрипт или .NET), Activity и WorkItem.
3. Загрузка и скачивание файлов через хранилище APS, асинхронное ожидание результата.
4. Запрашивать подтверждение у пользователя перед загрузкой чертежа, показывать стоимость, если она известна.
5. Включать только когда локального AutoCAD нет.

## 5. Web-просмотрщик

### Что должен уметь

- Показывать чертёж: масштабирование, перемещение, слои (включить и выключить), цвета и типы линий.
- Выделять объекты щелчком и рамкой. Показывать у выделенного тип, слой, `handle`, текст.
- Принимать от пользователя сообщение, привязанное к выделению: «в этих подписях заменить `0,35` на `0,36`».
- Показывать изменения агента: подсветка затронутых объектов, переключатель «до и после».
- Позже: синхронизация с живым AutoCAD.

### Архитектура

```
Claude Desktop (встроенный браузер)  <->  локальный сервер (в процессе MCP)  <->  движок (ezdxf, затем AutoCAD)
```

- Локальный HTTP-сервер запускается внутри MCP-сервера, чтобы использовать те же открытые чертежи. Слушает только `127.0.0.1`, на случайном порту, с одноразовым токеном в адресе.
- Сервер отдаёт сцену в JSON: объекты с `handle`, типом, слоем, цветом, геометрией, параметрами текста. Блоки раскрываются в виртуальные объекты.
- Веб-клиент рисует сцену в SVG (при большом числе объектов переходит на Canvas) и сам определяет объект под курсором. Рисование своими силами выбрано потому, что нужна привязка щелчка к `handle`. Готовые библиотеки (например `dxf-viewer`) стоит оценить на прототипе.
- Обновление при правках агента: сервер сообщает клиенту об изменении (SSE), клиент перерисовывает.
- Запуск: инструмент `open_viewer` поднимает сервер и возвращает адрес, агент открывает его во встроенном браузере (`preview_start` с `url`).
- Просмотрщик **ничего не пишет** в чертёж сам: правит только агент через инструменты MCP. Это исключает конфликт двух авторов.

### Как просмотрщик общается с агентом

| Уровень | Как работает | Надёжность |
| --- | --- | --- |
| A (первая версия) | Выделение и заметки хранятся на сервере. Инструменты MCP: `viewer_get_selection`, `viewer_get_messages`, `viewer_highlight(handles, подпись)`, `viewer_refresh`. Пользователь пишет в чат «смотри выделенное» или оставляет заметку, агент вызывает инструмент | Высокая, не зависит от возможностей приложения |
| B | Сообщения из просмотрщика доставляются агенту сами, через мониторинг потока событий сервера (инструмент `Monitor`) | Нужно проверить, как это работает в Claude Desktop |
| C | Запасной: агент читает страницу браузера (`read_page`, `javascript_tool`, снимок экрана) | Низкая, зависит от разметки страницы |

### Ограничения, о которых надо знать заранее

- Шрифты AutoCAD (`SHX`) в браузере недоступны, подписи рисуются приближённым шрифтом. Размеры текста будут отличаться от AutoCAD.
- Штриховки, размеры и сложные линии на первом этапе упрощаются.
- Для чертежей с десятками тысяч объектов нужна оптимизация (Canvas, фильтрация по видимой области). Порог определить измерением на прототипе.

### Порядок разработки просмотрщика

1. Прототип: сцена в JSON для `1-2.dwg`, SVG-отрисовка, масштабирование, слои.
2. Выделение щелчком и рамкой, панель свойств.
3. Заметки к выделению, инструменты уровня A, сквозной сценарий: выделил подпись, написал, агент поправил, просмотрщик обновился.
4. Подсветка изменений и «до и после».
5. Уровень B (проверка доставки событий), затем синхронизация с живым AutoCAD.

## 6. Тесты и критерии

- Набор тестовых чертежей: `1-2.dwg`, чертёж с динамическими блоками, с прокси-объектами, с внешними ссылками. Динамические блоки и прокси нужно получить у пользователя.
- Проверка «открыть и сохранить» на каждом движке: сравнение числа объектов, свойств и отрисовки до и после.
- Для каждой операции из списка «сложных объектов» зафиксировать, какие движки её выполняют корректно. По результатам обновить таблицу в разделе 3.
- Сквозной тест просмотрщика: выделить подпись, изменить текст через сообщение, убедиться, что в файле и в просмотрщике результат одинаков.

## 8. Плагин `3d-editor`: движки для 3D и BIM

Решения пользователя:
- BIM-задачи решаются другими движками: Revit, Forma, Navisworks.
- Fusion это один из способов работы с 3D-моделями, его выбирают по объекту и задаче.
- Все движки для 3D живут в одном плагине `plugins/3d-editor/` этого репозитория. Плагин `dwg-editor` остаётся в корне.

Всё, что ниже сказано о возможностях продуктов Autodesk, это общие знания. Каждую строку нужно подтвердить на этапе F0.

### Движки

| Движок | Для каких объектов и задач | Как подключать (проверить) | Что выяснить |
| --- | --- | --- | --- |
| Fusion | 3D-модели изделий: детали, сборки, обработка, симуляция | Расширение Autodesk Fusion в Claude Desktop (подключено, инструменты не изучены), встроенный API скриптов (Python, C++) | Список инструментов расширения, лицензия, что можно менять, а что только читать |
| Revit | BIM здания и инженерных систем | API Revit (.NET), Dynamo, облачные сервисы Autodesk | Есть ли лицензия Revit и какая версия, нужен ли живой Revit |
| Forma | Ранние проработки площадки и здания в облаке | Облачные интеграции и расширения Forma | Нужна ли учётная запись, что открыто через API |
| Navisworks | Сводные модели, проверка коллизий, координация | API Navisworks (.NET) | Лицензия, режим «только чтение» или правка |
| Файловый уровень (моё предложение, не из ваших решений) | Простое чтение и правка файлов без САПР: IFC для BIM, сетки и STEP для 3D | Библиотеки Python (например IfcOpenShell для IFC), по аналогии с `ezdxf` для DWG | Подходят ли библиотеки под ваши форматы и задачи |

### Выбор движка по объекту и задаче

Предварительная таблица, будет уточнена на F0:

| Объект и задача | Движок |
| --- | --- |
| Деталь или сборка изделия, обработка, симуляция | Fusion |
| Модель здания и инженерных систем, правка элементов | Revit |
| Ранняя проработка площадки и здания | Forma |
| Координация моделей, коллизии, просмотр сводной модели | Navisworks |
| Обмен и простая правка без САПР (IFC, сетки, STEP) | Файловый уровень |

Если объект и задача не очевидны, агент спрашивает пользователя и не угадывает.

### Структура репозитория

Принят вариант A: `dwg-editor` остаётся в корне, новый плагин лежит в `plugins/3d-editor/`, в `.claude-plugin/marketplace.json` для него вторая запись с `"source": "./plugins/3d-editor"`. Установленные копии `dwg-editor` не ломаются. Имя маркетплейса `dwg-tools` оставляем, его смена ломает установленные копии. Поддержку источников-подпапок нужно проверить по документации Claude Code и `claude plugin validate`.

### Риски и вопросы

- Лицензии Revit, Navisworks, Forma, Fusion и условия автоматизации.
- Часть движков требует установленного продукта на ПК, часть облачная: нужны разные способы подключения и подтверждения пользователя.
- Если у расширения Fusion в Claude Desktop уже есть нужные инструменты, для Fusion плагин может свестись к навыкам и документации.
- Нужны ответы пользователя: какие объекты и задачи в приоритете (изделия или здания), какие лицензии есть, примеры моделей.
